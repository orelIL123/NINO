# חיבור NINO ל־Shopify

מדריך הפעלה. שני חלקים: **חיבור טכני** (פעם אחת) ו**הזנת מוצרים** (שוטף).

---

## חלק 1 · חיבור החנות

### שלב 1 — לפתוח את החנות

Shopify לא מגישה נתונים לחנות נעולה. בלי זה שום טוקן לא יעבוד.

`Settings` → `Plan` → לבחור תוכנית פעילה.

> **בדיקה:** אם `npm run shopify:check` מחזיר `"Online Store channel is locked"` — התוכנית עדיין לא פעילה.

### שלב 2 — להתקין את ערוץ Headless

`Sales channels` → חיפוש **Headless** → `Add channel` → `Create storefront`

זו הדרך הנכונה ל־Next.js. **לא** צריך Custom App ו**לא** צריך Dev Dashboard.

### שלב 3 — טוקן ציבורי (אופציונלי לפיצ׳רים מורחבים)

בתוך ערוץ Headless → `Storefront API` → **Public access token**.

מוצרים, קולקציות, חיפוש ועגלות נתמכים גם בלי טוקן ב־Storefront API הנוכחי.
טוקן עדיין נדרש לשדות ויכולות מוגנים כמו לקוחות, תפריטים ומטא־אובייקטים.

⚠️ הטוקן הזה, ולא אחר. אלה הטוקנים שנראים דומים ו**לא** יעבדו:

| מתחיל ב־ | מה זה | למה לא |
|---|---|---|
| `shpss_` | App secret key | הרשאות כתיבה — אסור בצד לקוח |
| `shpat_` | Admin API token | API אחר לגמרי |
| `atkn_` | Dev Dashboard token | לא שייך לחנות |
| 32 תווים hex | יכול להיות **API key** *או* Storefront token | שניהם באותו מסך ונראים זהים |

### שלב 4 — להגדיר

ב־`.env.local` (פיתוח) וב־Vercel → Settings → Environment Variables (פרודקשן):

```
SHOPIFY_STORE_DOMAIN=your-store.myshopify.com
SHOPIFY_STOREFRONT_ACCESS_TOKEN=<Public access token, optional>
```

### שלב 5 — לבדוק

```bash
npm run shopify:check
```

הסקריפט בודק שכבה־שכבה ואומר בדיוק מה תקוע. אם הכל ירוק — האתר כבר מושך מ־Shopify.

> **נפילה רכה:** אם Shopify לא זמינה או הטוקן שגוי, האתר ממשיך לעבוד עם קטלוג הדמו במקום ליפול. תראו את זה בלוגים כ־`[catalog] Shopify read failed`.

## חלק 2 · איך להזין מוצרים

**זה החלק שחשוב לקרוא לפני המוצר הראשון.** האתר ממפה שדות Shopify לקטגוריות, מותגים ופילטרים. הזנה לא עקבית = פילטרים שבורים, ותיקון של 200 מוצרים ידנית.

### מיפוי השדות

| שדה ב־Shopify | לאן זה הולך באתר | חובה |
|---|---|---|
| **Title** | שם המוצר | ✅ |
| **Vendor** | מותג (עמוד מותג + פילטר) | ✅ |
| **Product type** | קטגוריה | ✅ |
| **Tags** | קבוצה, מגדר, תגיות "חדש" | ✅ |
| **Media** | גלריית תמונות | ✅ |
| **Options** | בורר מידה וצבע | ✅ |
| **Price / Compare-at** | מחיר; אם יש Compare-at → מוצג כמבצע | ✅ |

### תגיות (Tags) — הכי חשוב

| תגית | אפקט |
|---|---|
| `new` | תג "חדש" + מופיע ב"חדש באתר" |
| `bestseller` | תג "הכי נמכר" + מדורג גבוה |
| `men` / `women` | סינון לפי מגדר |
| `clothing` / `shoes` / `accessories` | לאיזו קטגוריה ראשית שייך |

**דוגמה למוצר תקין:**

```
Title:        Oversized Dachshund Tee
Vendor:       NINO
Product type: T-shirts
Tags:         new, men, clothing
Options:      Size (S, M, L, XL) · Color (White)
Price:        149
```

### מידות וצבעים

האופציות **חייבות** להיקרא בדיוק כך:

- מידה → `Size` או `מידה`
- צבע → `Color` או `צבע`

שם אחר (`Sizes`, `גודל`, `מידות`) = בורר המידות לא יעבוד במוצר הזה.

### מלאי

`Track quantity` דלוק. מידה עם 0 יחידות מוצגת מחוקה ולא ניתנת לבחירה — אוטומטי.

### עברית ואנגלית

האתר דו־לשוני. להתקין את האפליקציה החינמית **Translate & Adapt** ולתרגם כותרת + תיאור.

בלי תרגום, האתר מציג את אותו טקסט בשתי השפות — לא נשבר, אבל לא מקצועי.

### תמונות

- מומלץ **מרובע** (1:1) או 4:5, מינימום 1200px
- התמונה הראשונה = תמונת הכרטיסייה
- Shopify מבצעת אופטימיזציה ומגישה מ־CDN אוטומטית

## מה עובר לניהול Shopify

מרגע החיבור, כל אלה מנוהלים ב־Shopify Admin (כולל מהאפליקציה בנייד) בלי לגעת בקוד:

מוצרים · תמונות · מלאי · מחירים · מבצעים וקופונים · הזמנות · לקוחות · תשלומים · משלוחים

**Checkout רץ אצל Shopify** — פרטי אשראי לא עוברים דרך האתר שלנו בכלל.

## בדיקה אחרי החיבור

`npm run shopify:check` גם מוודא היגיינת נתונים ומדווח, למשל:

```
✗ 3/50 no Size option
    oversized-tee, linen-shirt, wool-coat
```

אלה אזהרות, לא שגיאות — האתר עובד, אבל המוצרים האלה יאבדו סינון או בחירת מידה.
